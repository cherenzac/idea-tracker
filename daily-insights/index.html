Worked example: same data, different order

Start at c = 0. For each observation x, update c to (c + x) / 2. Move the value 12 through three zeros. Evaluate each final estimate on the same four observations:

  • 12 first: final estimate 0.75, mean squared error 32.0625.
  • 12 second: final estimate 1.5, mean squared error 29.25.
  • 12 third: final estimate 3, mean squared error 27.
  • 12 last: final estimate 6, mean squared error 36.

The arithmetic mean is 3 in all four orders. On this fixed sample, mean squared error at any estimate c is 27 + (c − 3)². That explains the batch baseline without assuming it will generalize to a changing stream.

This is a one-centroid, fixed-step illustration with no reassignment. It is not an implementation or benchmark of e-means, which uses a different update and discusses centroid finalization.

Worked example: one late order, two answer keys

In this fictional warehouse, three Q1 orders are visible before April 2. A fourth order, placed March 29, arrives April 3. An April 1 order is already visible but falls outside Q1. To check the counts, filter ordered_on to January 1 inclusive through April 1 exclusive, then filter ingested_on to earlier than the snapshot cutoff.

  • Fresh April 4 query: 4. A fixed key of 3 marks this wrong; the April 4 reference correctly passes it.
  • Stale April 2 cache: 3. A fixed key of 3 marks this right; the April 4 reference correctly fails it.
What the evaluation harness should record

For regression tests, run both versions on the same frozen snapshot and metric definition. For live evaluations, record the intended and observed snapshot versions separately, along with the metric version and authorized data scope. Run an independent reference query against the intended snapshot. If that snapshot cannot be recovered, leave the answer unscored and record the missing evidence; do not count it as model drift.

A timestamp is not a snapshot ID: backfills and corrections can change results even when a query uses the same date filter. This example illustrates a test design, not a claim about a shipping dbt feature.
